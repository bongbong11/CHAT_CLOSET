# 끼끼의상실

SillyTavern 캐릭터·페르소나의 취향, 옷장, 현재 착장을 관리하는 클라이언트 확장입니다. 별도 서버 플러그인은 필요하지 않습니다. 구현 구조·수정 순서·배포 검수는 [BLUEPRINT.md](BLUEPRINT.md)에 정리합니다.

## 설치와 시작

실리의 **확장 → 확장 설치**에서 `https://github.com/bongbong11/CHAT_CLOSET`를 설치하고 새로고침합니다. 마법봉 메뉴의 끼끼 얼굴을 눌러 **끼끼의상실 → 설정**에서 **사용함**을 켜고 연결 프로필을 선택합니다. 프로필은 고르면 바로 자동 저장되며 다음 작업부터 사용합니다. 목록은 생성·수정·삭제와 선택창 열기 시 자동 갱신됩니다. **연결 확인 (선택)**은 별도 점검용이며 프로필 선택의 조건이 아닙니다. API 키는 실리 Connection Manager에서 관리하며 확장에 별도로 저장하지 않습니다. 개별 캐릭터 채팅을 지원하며 그룹 채팅은 지원하지 않습니다.

1. **선택지**에서 캐릭터 또는 페르소나를 고릅니다.
2. **분석 자료 가져오기**에서 해당 대상의 시트와 연결된 로어북을 불러옵니다. 캐릭터는 설명·성격 요약, 페르소나는 현재 페르소나 시트를 사용합니다.
3. 필요한 로어북 엔트리만 체크하고 취향 분석을 실행합니다. 초기 취향 분석에 채팅·기억은 보내지 않습니다.
4. **취향 보기**에서 영어 보고서를 읽습니다. 작은 **번역하기** 버튼으로 한국어 번역을 생성하며 번역과 선택 언어는 서버에 저장됩니다. 영어 원본·옷장은 바뀌지 않습니다. **원문 수정 → 수정 저장**으로 확정한 값은 재분석 시 보존됩니다.
5. 모델에게 보내는 프롬프트의 참고 자료 위치에 아래 매크로를 한 번 넣습니다. 답변에 출력하라는 인포블록 양식 바깥에 두고, 기존 인포블록의 의상 출력 항목은 제거합니다. 화면 표시 전용 템플릿에는 넣어도 모델에 전달되지 않습니다.

```text
{{kikki_outfit}}
```

매크로에는 **현재 착용한 옷의 영어 이름·색·브랜드·필요한 착용 상태만** 들어갑니다. 판독 규칙·취향·신체 조건·옷장·날씨·변경 이유는 주입하지 않습니다. 전부 벗었거나 확인된 옷이 없으면 빈 내용입니다. 같은 옷이면 같은 짧은 내용을 재사용하며, 맥락 없는 "이전과 같음"만 전달하지 않습니다.

기존의 아래 태그 방식도 계속 사용할 수 있습니다. 매크로와 태그가 함께 있거나 반복되어도 최종 요청에는 한 곳만 채웁니다. 원래 프리셋·채팅 메시지를 수정하지 않고 보내는 요청에서만 처리합니다.

```text
<kikki_outfit>
</kikki_outfit>
```

## 착장 판독과 결정

롤플 생성 전에는 저장된 착장을 즉시 참고합니다. 판독 모델이나 서버 동기화를 기다리지 않고, 롤플 모델에게 JSON·착장 목록 생성을 요구하지 않습니다. **롤플 답변 완료 후** 확장의 연결모델이 짧은 장면 변화만 추출합니다. 실제 착장 유지·보충·교체는 확장 코드가 결정합니다. 옷장으로 해결되지 않는 필요한 품목만 별도 생성합니다. 정상적인 변화 없음 응답에서도 아직 확인하지 않은 기존 추정 착장을 저장된 상황과 대조합니다. 같은 상태·옷·옷장·생성 설정은 반복 교체하지 않습니다. 대화의 명시적 착용과 수동 선택은 우선하며, 옷 데이터가 불명이라는 이유만으로 갈아입히지 않습니다.

- 실제 사용자 입력과 AI 답변이 먼저입니다. 확장은 착장을 위해 이야기·행동·구매를 만들지 않습니다.
- 장소, 신체 조건, 활동 단계, 계절·날씨의 확인된 기준값을 인물별로 유지합니다. 새 근거가 없으면 그대로 두고, 회복 등 명확한 변화가 있을 때만 해제합니다.
- 현재 옷이 적합하면 유지합니다. 조합 다양성이나 반복된 임신·부상 언급만으로 갈아입히지 않습니다.
- 일반적인 외출 완료에서는 필요한 신발·누락된 옷만 보충합니다. 현재 이야기에서 신발 없이 뛰쳐나간 것이 명시되면 맨발을 유지합니다. 오래전 맨발·알몸 상태를 영구 제약으로 삼지 않습니다.
- 사적인 방 이동, 손 씻기, 샤워 계획은 환복 이유가 아닙니다. 실제 목욕·타월·탈의 상태와 외출을 구분합니다. 수면 복장은 롤플이 정합니다.
- 부상·임신 등 확인된 조건에 맞게 필요한 부분만 조정합니다. 일반 임신만으로 전부 임산부복으로 바꾸지 않습니다. 명시된 후기 임신의 허리 압박, 팔 고정의 착탈 제약 등 간단한 착용 조건을 활용하며 진단·임신 단계·의료기구를 새로 만들지 않습니다.
- 소매를 걷거나 단추를 푼 것은 같은 아이템의 착용 상태로 저장합니다. 옷의 원래 브랜드·색·기능을 바꾸지 않습니다. 환자복·타월은 정규 외출복 기억을 덮지 않습니다.
- 같은 장소의 일반 대화와 중복 완료 이벤트는 모델 호출 없이 유지합니다. 코드가 환복·이동·신체 변화·큰 시간 변화 등의 후보를 감지하고, 모델이 실제 사건/계획/회상을 구분합니다. 간접 표현을 놓쳤다면 **현재 옷 보기**로 다시 판독할 수 있습니다.
- **읽을 최근 채팅 턴 수**(1~50, 기본 8)는 전송할 대화의 최대 범위입니다. 사용자 입력과 이어지는 답변을 1턴으로 셉니다. 유효한 저장 기준점이 있는 평소 자동 판독은 이 범위 안의 미처리 새 대화 전부와 이미 처리한 직전 최대 1턴만 보냅니다. 최초 판독·유효 기준점 소실·수동 **현재 옷 보기**는 기존처럼 설정된 최근 범위를 읽습니다. 저장된 신체 상태·착장도 함께 참고하며, 장면 요청에는 전체 시트·로어북·옷장·긴 취향 보고서를 보내지 않습니다. 변화 감지 기준과 판독 프롬프트는 유지합니다.

확장용 프롬프트는 영어이며 역할별 규칙과 반환 형식을 공유합니다. 장면 판독은 짧은 사실 응답, 옷장 생성은 필요한 의류 레코드만 받습니다. 장면 판독과 복구의 응답 상한은 5,000토큰입니다. 원본 응답의 종료 사유와 사용량을 로그에 남깁니다. 한도 초과 또는 잘린 JSON은 일부만 복구해 적용하지 않고 원래 프롬프트·자료로 한 번만 다시 판독합니다. 재시도도 불완전하면 기존 데이터를 유지합니다. 그 외 형식 오류는 기존 한 번의 복구 예산에서 처리합니다.

## 화면 표시

설정의 **착장정보 표시 방식**에서 두 가지를 선택합니다. 기존 설치는 떠 있는 아이콘 방식으로 시작합니다.

- **떠 있는 끼끼 아이콘:** 지금처럼 화면의 끼끼를 누르면 작은 말풍선이 열립니다. 다시 누르면 닫힙니다. PC·모바일 위치를 따로 기억하고 화면 밖으로 나가지 않게 보정합니다. **끼끼 위치 고정**도 지원합니다. 작은 창 제목 옆에서 **현재 옷 보기 / 의상실 열기**를 사용할 수 있습니다.
- **답변 아래 메모:** AI 답변 아래에 디자이너 메모 형태의 **착장정보**를 기본 펼침으로 붙입니다. 끼끼를 누르면 얼굴·제목 한 줄로 접히고 다시 누르면 펼쳐집니다. PC는 두 인물을 좌우로, 모바일은 실제 인물 이름 아래에 위아래로 함께 표시합니다. 의상명과 브랜드는 잘리지 않게 줄바꿈하고, 브랜드는 더 작은 글씨로 표시합니다. 접기 상태는 저장되며 표시 전환은 모델을 호출하지 않습니다. 제목 옆 작은 **현재 옷 보기 / 의상실 열기** 버튼은 접힌 상태에서도 사용할 수 있습니다. 현재 옷 보기는 항상 현재 채팅의 최신 장면을 읽습니다. 작업 중 연속 클릭은 중복 요청하지 않습니다. 이 방식에서는 떠 있는 아이콘을 숨깁니다. 본창은 마법봉이나 확장 설정에서 계속 열 수 있습니다.

설정의 **과거 착장정보 보관 개수**는 성공적으로 저장한 답변별 기록 1~20개, 기본 **1개**입니다. 초과 기록은 오래된 것부터 정리하며 아직 판독하지 못한 답변이 생겼다는 이유로 기존 저장 기록을 지우지 않습니다. 개수를 늘려도 이미 지운 과거 기록은 복원하지 않습니다. **최신 판독·현재 착장은 이 개수와 별도로 계속 유지**하며 판독할 때마다 갱신합니다. **읽을 최근 채팅 턴 수**와도 별개인 설정입니다.

메모는 확장이 별도로 그리는 화면이므로 채팅 원문이나 롤플 토큰에 포함되지 않습니다. 새로고침해도 유효한 최근 기록을 다시 표시합니다. 기록 없는 과거 답변에는 빈 카드들을 붙이지 않습니다.

리롤·스와이프·메시지 수정·삭제·하이드로 답변별 기록이 무효가 돼도 **해당 채팅에서 마지막으로 확인한 착장과 판독 상태는 유지**합니다. 본창·플로팅·최신 답변 메모와 매크로는 이 상태를 사용하며, 새 답변을 아직 판독하지 않았으면 메모에 마지막 확인 착장임을 표시합니다. 구조 변경 자체는 모델을 호출하지 않습니다. 다음 새 답변 완료 또는 **현재 옷 보기**에서 기존 착장을 기준으로 실제 변경 사항만 반영합니다. 다른 채팅·브랜치의 상태를 가져오지 않으며 **현재 채팅 데이터 삭제**로 수동 초기화할 수 있습니다.

유효한 기준점이 없는 재판독은 삭제된 장면의 신체 조건·탈의 기억을 이어받지 않고 남아 있는 최근 채팅을 사용합니다. 저장된 취향과 소유 옷은 유지합니다.

의상명과 브랜드는 생성할 때 영어 원본과 짧은 한국어 표시명을 함께 저장합니다. 옷장을 열 때마다 번역하지 않습니다. 이름은 색·의류 종류 중심으로 짧게, 브랜드는 작게 표시하며 상세 소재·구조는 영어 내부 기록에 둡니다. 이미 있는 정상적인 영어 원본이나 표시명은 임의로 바꾸지 않습니다. 구버전의 표시명 누락은 옷장 재생성 시 착용 중인 옷의 원본을 보존하며 보완합니다.

본창은 기존 다이어리 비율을 유지한 중앙 모달입니다. 모바일은 작은 글씨·좁은 행 간격, PC는 읽기 편한 착장 본문을 사용합니다. 실리 테마에 맞춰 밝고 어두운 종이 색을 적용합니다. 판독 중에는 오른쪽 아래 작은 토스트 **“의상을 맞춰보고 있습니다”**가 나오고, 누르면 안내만 사라집니다.

## 옷장

**새 옷 추가**는 선택지 탭에서 정합니다. 자동 추가 끄기/적게/보통/많이를 서버에 저장하며, 예전 선택값도 유지합니다. 적게는 필수 커버리지·신체 제약·보온, 보통은 명확히 맞지 않는 용도까지, 많이는 실제 장면에 필요한 방수 같은 전용 기능까지 보충합니다. 적합한 보유품을 먼저 사용하고, 옷장으로 해결할 수 없는 품목만 생성·저장해 재사용합니다. 끄기에서도 대화에서 실제 입은 새 옷은 기록합니다. 단순 다양성·새 턴은 생성 사유가 아닙니다. 브라·팬티·양말은 별도 슬롯이며 예전 한국어 이름도 인식합니다. 생성 결과는 모델에 관계없이 요청 ID와 큰 카테고리로 연결하며 이름·색·브랜드 표현의 차이로 거절하지 않습니다. 속옷은 브라/브라렛, 팬티/복서, 양말/덧버선/스타킹, 속셔츠 그룹을 구분하고 소품은 장신구(jewelry)와 일반 소품(utility)을 구분합니다. 필요한 요청에만 짧은 matchGroup을 전달하며, 가능한 아이템을 특정 목록으로 제한하지 않습니다. 기존 옷장에서 고르는 적합성 판단과 실제 착장 주입 계약은 유지합니다.

**기본 옷장 구성** 하나로 적게/중간/많이를 선택합니다. 주요 의류는 아래 수만큼 서로 다른 디자인을 만들고, 속옷·액세서리는 작은 실용적인 구성으로 만듭니다. 양말·벨트 복제품으로 수량을 채우지 않습니다.

| 구성 | 상의 | 하의 | 겉옷 | 신발 |
| --- | ---: | ---: | ---: | ---: |
| 적게 | 4 | 3 | 1 | 2 |
| 중간 | 7 | 5 | 3 | 3 |
| 많이 | 10 | 7 | 5 | 5 |

직업·일상·실내 생활과 실제 설정에 따라 배분하며, 전용 잠옷은 기본 옷장 생성에서 제외합니다. 명시적인 소유 제한이나 적용 불가능한 종류만 예외로 둡니다. 필요한 옷이 나중에 추가되는 것은 허용하며 생성 목표를 소유 한도로 사용하지 않습니다.

**옷장 · 착장 수정**은 인물/카테고리별 목록과 앞쪽 선택란으로 구성합니다. **이 카테고리 새로 생성**은 해당 인물의 선택 종류만 바꿉니다. 취향 보기 옆 **옷장만 새로 생성**은 팝업에서 인물을 선택해 전체 옷장을 바꿉니다. 둘 다 현재 입은 옷과 취향을 유지하며, 실패하면 이전 목록을 보존합니다. 현재 착장에서 임의로 바꾼 내용은 **착장 저장**으로 확정합니다.

공산품은 현대 SPA·중고품까지 원래 브랜드를 표시합니다. 시대·세계관에 따라 공방·제작자·수제 정보를 쓰며, 현대 브랜드를 판타지에 강제하지 않습니다. 자동 환복을 유도하던 구 조합 다양성/새 옷 양 옵션은 제거하고 필요한 품목만 추가하도록 통일했습니다.

## 작업과 브랜치

취향 분석·옷장 생성·번역·판독은 확장 창을 닫아도 계속됩니다. 진행 중에는 기존 ×로 닫고 채팅을 이어갈 수 있으며 완료 후 창을 강제로 다시 열지 않습니다. 중복 작업을 막고, 롤플 답변 중지는 옷장 작업을 취소하지 않습니다. 생성 중 도착한 새 채팅은 작업 뒤에 판독합니다. 연결 프로필을 바꿔도 시작한 작업은 원래 연결로 끝내며 다음 작업부터 새 연결을 사용합니다.

브라우저 페이지 종료/새로고침은 요청을 중단합니다. 휴대폰 화면 잠금이나 백그라운드 실행은 브라우저 정책에 따라 지연·중단될 수 있습니다. 삭제·채팅/브랜치 전환 뒤 늦게 도착한 응답은 적용하지 않습니다.

캐릭터 기본 취향·옷장과 스토리별 브랜치를 구분합니다. 새 채팅에서는 새 스토리·현재 상태 복제·기존 브랜치 연결을 선택합니다. 페르소나가 달라지면 새 브랜치에서 해당 페르소나를 분석합니다. 현재 상태 복제는 원본 브랜치의 페르소나를 확인하며, 다른 인물의 자료를 자동으로 이어 쓰지 않습니다. 리롤·스와이프·수정·하이드로 답변 연결이 바뀌어도 해당 방의 마지막 확정 착장·판독은 유지하며 다음 판독에서 최신 사실을 반영합니다. 상태 이력 5개·최근 조합 10개·복원 체크포인트 최대 80개를 보관하며(연결 채팅별 최신 기준점은 삭제하지 않아 예외적으로 추가 보존), 답변 표시용 짧은 기록은 별도로 저장합니다. 숨긴 답변에는 메모를 표시하지 않습니다.

## 서버 자동 저장과 정리

같은 실리 서버·계정의 PC와 모바일이 데이터를 공유합니다. 설정·분석·판독·번역·메모의 접기 상태는 자동 저장하며, 수동 편집 중인 착장·보고서는 저장 버튼으로 확정합니다. **서버 저장됨**을 확인하고 다른 기기로 이어가세요. 접속·화면 복귀·15초 주기로 서버 변경을 확인합니다. 다른 서버/계정과 공유하지 않습니다.

실리의 [기본 파일 API](https://github.com/SillyTavern/SillyTavern/blob/release/src/endpoints/files.js)를 사용해 `data/<계정>/user/files/`에 저장합니다.

- `kikki-closet-state.json`: 공용 설정과 캐릭터 파일 목록.
- `kikki-closet-character-<고정 식별자>.json`: 해당 캐릭터의 취향·옷장·브랜치·페르소나·착장·번역·복원/표시 기록.

프리셋·연결 프로필·모델 이름을 저장 구분에 사용하지 않습니다. 같은 파일을 갱신하며 별도 임시·회전 백업·채팅별 조각 파일을 만들지 않습니다. 저장 중에는 공용 파일의 복구 정보를 먼저 기록하고 검증 후 제거합니다. 중단되면 다음 접속이나 **서버 다시 연결**에서 복구합니다. 기본 파일 API에 기기 간 원자적 잠금이 없으므로 정확히 동시 편집까지 보장하지는 않습니다.

기존 한 파일 저장 자료는 자동 이전합니다. 오래된 브라우저 저장소만 있다면 먼저 그 기기로 업데이트하고, 서버 저장·재조회가 성공한 뒤에만 브라우저 원본을 지웁니다. 서버가 먼저 만들어졌다면 **이 브라우저의 이전 데이터 가져오기**로 기존 자료를 별도 브랜치로 가져올 수 있습니다. 이번 업데이트는 기존 옷장·취향을 재생성하지 않고 필요한 필드만 보완합니다.

설정의 삭제 버튼 아래에 각 범위를 안내합니다.

- **현재 채팅 삭제:** 해당 채팅의 착장·판독·표시 기록 초기화. 취향·기본 옷장 유지. 공유 브랜치는 분리해 다른 채팅 보존.
- **캐릭터 전체 삭제:** 해당 캐릭터의 모든 브랜치와 전용 서버 파일 삭제. 다른 캐릭터·공용 설정 보존.
- **전체 삭제:** 모든 캐릭터 생성 자료·전용 파일·확장 설정 삭제. 실리 캐릭터 카드와 채팅 원문 보존. 공용 파일에는 오래된 기기의 자료 부활을 막는 빈 삭제 표시만 유지.
- **불필요한 데이터 정리:** 소유를 확인할 수 있는 알려진 미사용 파일, 삭제 대기 기록, 만료 번역, 한도를 넘은 복원 기록, 현재 채팅에서 삭제된 메시지/스와이프의 표시 기록과 참조 없는 표시 스냅샷을 정리. 현재 채팅의 AI 답변·스와이프에 남은 내부 착장 태그도 제거. 사용자 원문·일반 서식·현재 자료·유효한 옷장은 보존.

정리는 모델 호출이나 별도 로그 파일을 만들지 않습니다. 파일 존재를 먼저 확인하고, 소유를 확인할 수 없는 파일은 지우지 않습니다. 서버/설치 폴더 전체나 다른 채팅 파일을 검색하지 않습니다. 실패는 완료로 표시하지 않고 재시도 정보를 유지합니다. 실리 채팅 삭제 이벤트에서는 연결을 제거하며 마지막 연결이 사라진 브랜치를 삭제합니다. 외부에서 직접 지운 채팅은 브랜치 관리에서 정리하세요.

## 내부 출력 차단과 개발 검사

모델이 실수로 `<kikki_outfit>…</kikki_outfit>`을 답변에 복사하면 부분 스트림부터 저장된 스와이프까지 내부 블록을 제거합니다. 일반적인 의상 서술은 유지합니다. 신형 실리는 공식 포맷터 훅, 구형은 기본 Regex 확장으로 차단합니다. 별도 플러그인은 필요하지 않습니다. 사용자 정규식은 수정하지 않으며 전체 삭제 시 자체 규칙만 제거합니다.

개발 검사는 `npm run check`, `npm test`, `npm run test:browser`로 실행합니다. 브라우저 검사는 fixture ST + 실제 확장 모듈을 사용하며 실제 사용자 서버/원격 모델 검수와 구분합니다. Windows 기본 브라우저는 headless Edge, CI는 Chromium입니다. 배포 전 검토 기준과 남은 실기 검사는 [BLUEPRINT.md](BLUEPRINT.md)에 기록합니다.


## 수집된 상황 확인과 진단 로그

현재 착장 탭·플로팅 작은 창·답변 아래 메모의 **수집된 상황 정보**를 펼치면 인물별 장소, 공간, 활동, 신체 상태, 착용 제약, 계절, 기온, 날씨, 용도와 현재 예외를 확인할 수 있습니다. 계절·기온·날씨는 특정 태그 이름에 종속되지 않고 백틱·표·목록·JSON·HTML 등에서 한영 라벨의 명시값을 읽어 짧은 영어 필드로 보완합니다. 날씨·기온이 모델의 scene 요약에만 있거나 scene이 changes 안에 잘못 들어 있어도 복구합니다. 인포 없는 본문의 기후 묘사는 기존 판독 모델이 해석하며, 근거 없는 숫자 기온을 만들지 않습니다. 유효한 이전 값은 유지하고 근거가 없는 값만 미확인으로 표시합니다. 같은 인포가 반복돼도 본문에서 확인한 새 값을 되돌리지 않으며, 명시된 작은 기온 변화는 추가 모델 호출 없이 저장합니다. 화면에는 가을 / 14℃ / 흐림 같은 짧은 값만 표시합니다. 상세 신체 사실/제약 원문은 영어일 수 있습니다. 열람 시 모델을 호출하지 않습니다.

설정 또는 실리 확장 패널의 **전체 로그 복사**로 현재 보관된 모든 작업을 한 번에 복사합니다. **작업·오류 로그** 안에서도 표시 필터나 접힘 상태와 관계없이 전체 복사가 가능합니다. **전체 복사본 보기**는 로그를 하나의 텍스트로 보여 주며, 자동 갱신 없이 전체 선택·직접 복사할 수 있습니다. 자동 복사가 차단되면 이 화면이 열립니다. **이 작업 복사 / 로그 비우기**도 계속 사용할 수 있습니다. 요청에 보낸 최근 문맥, 모델 원문 응답, 정리한 사실, 적용 전후 상태, 저장 결과와 오류 원인을 같은 작업 번호로 추적합니다. API 키/인증 헤더/쿠키는 수집하지 않습니다. 로그는 최근 30개/총 2MiB 이내 메모리에만 보관하고 새로고침하면 비워집니다.

표기·선택 필드·표시 번역 차이는 코드가 정리합니다. 의미가 분명한 정보는 처리하고 불명확한 부분은 유지합니다. 문장형 응답은 기존 1회 복구 예산에서 내용 해석을 시도합니다. 정상 changes 빈 응답은 변화 없음으로 처리하며 수집된 상황 표시를 지우지 않습니다.

현재 옷 보기는 최신 답변과 이어진 사용자 입력을 다시 읽고 이전 문맥은 배경으로 구분합니다. 긴 답변은 끝의 인포블록도 보존하고 장식된 장소 표기를 읽습니다. Vertex 등의 404/인증/사용량/서비스 오류는 응답 형식 오류와 구별하며 형식 복구로 재요청하지 않습니다. 404는 연결 프로필의 모델 ID·지역·프로젝트 접근 가능 여부를 확인해야 합니다.


신체 조건은 지속 상태입니다. 임신·입원 치료·부상·깁스 등은 새 사실만 추가하고, 명시적으로 해소된 항목만 제거합니다. 언급이 없거나 빈 배열을 받았다는 이유로 초기화하지 않습니다. 퇴원 시에는 입원만 해제하고 남아 있는 임신·부상과 착용 제약은 유지합니다. 일상 활동 요약은 수집하지 않으며 옷과 관계있는 단계와 신체 제약만 참고합니다.

콘솔에는 작업 완료·실패·취소 시 작업당 접힌 묶음 하나를 출력합니다. 펼치면 수집·모델 응답, 착장 판단, 저장·결과, 경고·오류로 구분됩니다. 경고/오류 개수는 묶음 제목에도 표시하고, 단계별 시각과 순서를 보존합니다. 진행 중 상세 내용은 확장의 작업·오류 로그에서 즉시 확인·복사할 수 있습니다. 판독 범위에는 일반 축소 판독(`incremental`), 전체 범위 판독(`full`), 수동 재판독(`manual`) 구분과 새 대화·이전 문맥의 메시지 수 및 글자 수를 남깁니다. 실제 호출과 복구 재호출은 연결모델 요청의 시도 번호로 구분하고, 제공되는 토큰 사용량은 응답 로그에서 확인합니다. 글자 수는 토큰 수가 아닙니다. 다른 확장이나 연결 서비스 자체의 콘솔 출력은 변경하지 않습니다.
